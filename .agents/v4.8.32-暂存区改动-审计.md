## 3. 性能优化与三大隐患针对性修复

### 3.1 核心热路径无锁化
1. **反代热路径完全无锁化（Zero-Lock Hot-Path）**：
   - `src-tauri/src/proxy/cache_manager.rs`：分层缓存统计计数器重构为 `AtomicU64`（`Ordering::Relaxed`），`inc_total()`、`inc_hits()`、`inc_misses()` 实现无锁硬件级原子自增。
   - `src-tauri/src/proxy/monitor.rs`：监控模块的 `total_requests`、`success_count`、`error_count` 同样迁移为 `AtomicU64`，彻底移除请求日志记录链路上的 `stats.write().await` 写锁开销。
2. **UI 展开动画 GPU 化与按需渲染**：
   - `IpAccessLogs.tsx` 的折叠行采用 CSS Grid `grid-rows-[0fr]` <-> `grid-rows-[1fr]` 过渡，避免传统 max-height 引起的严重重排（Reflow）；同时引入 `openedIds` 集合进行懒挂载，初次渲染不产生多余 DOM 节点。

### 3.2 审计发现的三大隐患与二次深度修复闭环（100% 修复完毕）

#### 🛠️ 修复 1：根治海外 IP / 无评分 IP 缓存穿透与后台无限死循环重查
- **问题根因**：原代码在 `geoip.rs:query_single_ip` 与 `security_db.rs:get_stale_geo_ips_with_connection` 中，强制要求 `risk_score.is_some()` 才判定为有效缓存。海外 IP（如 `8.8.8.8`）在百度接口中本身就不带 `risk_score`，导致本地库查无评分，系统将其判定为永久 stale，后台每周期无休止重新发起 HTTP 请求打百度，极易导致 IP 被百度封禁。
- **修复措施**：
  - `geoip.rs`：移除 `query_single_ip` 中的 `geo.risk_score.is_some()` 过滤，库中存在成功记录即直接返回。
  - `security_db.rs`：`get_stale_geo_ips_with_connection` 仅依据 30 天 TTL（`*queried_at < fresh_after`）判定过期，不再将合法的无评分 IP 判定为过期，彻底消除无限重查。

#### 🛠️ 修复 2：根治 SQLite 冷启动会话标题回填饥饿与 I/O 浪费
- **问题根因**：`proxy_db.rs` 中的 `backfill_session_titles` 在应用启动时执行 `WHERE session_title IS NULL LIMIT 1000`。普通对话日志本无标题且提取不出，导致启动时反复从磁盘全量加载并反序列化这 1000 条普通大报文，后续第 1001 条以后的真实标题永远得不到回填。
- **修复措施**：在 SQL 查询端添加关键词初筛：
  ```sql
  WHERE session_title IS NULL 
    AND (request_body LIKE '%title%' OR request_body LIKE '%标题%' OR response_body LIKE '%"title"%')
  LIMIT 500
  ```
  精准过滤候选集，消除启动大报文 I/O 开销与饥饿问题。

#### 🛠️ 修复 3：前端 IP 画像缓存防膨胀（LRU 500）与 Single-Flight 单飞并发
- **问题根因**：`ipThreatCache.ts` 原本全局 `MEMORY_CACHE` 无上限且每次同步全量写入 `sessionStorage`（易触发 5MB 超限）；缺乏并发请求去重。
- **修复措施**：
  - 引入 `MAX_CACHE_SIZE = 500` 与 `MAX_SESSION_ENTRIES = 200`，自动 LRU 淘汰最老条目。
  - 增加 `IN_FLIGHT: Map<string, Promise>` 单飞机制，同 IP 并发时复用同一个 Promise，杜绝重复网络请求。
  - `saveToSessionDebounced` 防抖节流写入，避免阻塞 UI。
  - `enrichIpListGeo` 升级为并发受控触发，提升页面加载速度。
