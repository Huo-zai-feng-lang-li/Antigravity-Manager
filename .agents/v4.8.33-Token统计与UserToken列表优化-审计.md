## 2. 核心审计维度核验

### 2.1 功能闭环验证 (Functional Closed-Loop)
- **自然日统计全链路闭环**：
  - **后端**：在 `token_stats.rs` 中通过 `today_start_hour_bucket()` 获取当天 `YYYY-MM-DD 00:00`，通过 `today_start_timestamp()` 获取本地零点精确时间戳。
  - **Tauri IPC + REST 双模支持**：无论是桌面端内部直接调用还是第三方 HTTP 代理调用，6 个今日统计接口（hourly, summary, by-account, by-model, model-trend, account-trend）全数映射并验证无阻断。
  - **前端视图响应**：`TokenStats.tsx` 顶部切换至“今日”时，通过 `fetchIdRef` 防竞态取消旧请求，数据即时拉取并渲染，URL SearchParams 同步更新为 `?range=today`。
- **UserToken 交互闭环**：
  - **搜索与过滤**：支持用户名、备注描述、以及任意长度/片段 Token（含完整 Token 粘贴）的全文本过滤，不再受此前 8 字符切片的限制。
  - **额度使用率梯级告警**：`getTokenStatus` 根据使用百分比（$\ge 90\%$ 红色危险，$\ge 70\%$ 橙色预警）自动标识 Badge，配合额度双进度条直观呈现。
  - **行级折叠详情**：点击行展开，展示 IP 限制、服务宵禁时间、创建时间及最后使用时间，不占用主表格横向宽度。

### 2.2 缺陷排查与根本原因修复 (Defect Analysis & Fixes)
- **【时区断层 Bug 彻底根治】（置信度：10/10）**：
  - **根因**：原代码 `today_start.and_utc().timestamp()` 错误将本地午夜判定为 UTC 午夜，导致东八区（UTC+8）的起计时间戳偏移至当天上午 08:00:00，凌晨 0 点至 8 点的数据在分模型、趋势图查询中被过滤漏计，而小时汇总查的是字符聚合表，导致页面上下两部分总数矛盾。
  - **修复**：采用 `chrono::Timelike::num_seconds_from_midnight()` 动态扣减距零点秒数：`now.timestamp() - seconds_since_midnight as i64`，并新增单元测试 `test_today_start_timestamp_aligns_with_local_midnight`，实测保证 100% 对齐本地零点。
- **【搜索框 Token 截断缺陷修复】**：
  - **根因**：原逻辑 `token.token.substring(0, 8).includes(q)` 导致用户粘贴完整 Token 进行检索时必然匹配失败。
  - **修复**：放开为 `token.token.toLowerCase().includes(q)`，支持前缀、全文与任意哈希段检索。
- **【DOM 动画规范与代码冗余消除】**：
  - 移除表格 `tbody` 中 `<AnimatePresence mode="popLayout">` 与 `<React.Fragment>` 的直接作用，避免多行折叠/过滤时的布局警告。
  - `TokenStats.tsx` 中的本地 `formatNumber` 闭包与公共 `src/utils/format.ts` 中的 `formatTokenCount` 统一口径，消除冗余代码。

### 2.3 性能与资源审计 (Performance & Resource)
- **热路径零开销**：代理监控中间件 `monitor.rs` 仅在流式响应结束时做一次轻量级 Json 键值嗅探，未引入任何运行时额外锁。
- **动画重绘优化**：`ConversationView.tsx` 放弃了 JavaScript 测量高或者 `max-height` 猜测，改用 CSS Grid `grid-rows-[1fr]` 到 `grid-rows-[0fr]` 硬件加速过渡，极大降低了长对话日志展开时的布局抖动（Layout Shift）。
- **SQL 执行效率**：`token_stats.rs` 中的查询全部命中现有复合索引（`idx_token_timestamp_model`, `idx_token_timestamp_account`），今日数据查询单次均在 1ms 内完成。

## 4. 架构洞察 (Architecture Insights)

- **时间维度的双轨设计建议**：当前 SQLite 中存储了字符串形式的 `hour_bucket`（`%Y-%m-%d %H:00`）和 Unix epoch 整数 `timestamp`。字符串 bucket 便于按自然小时离散聚合，而 epoch 整数适于区间比较与趋势拟合。在涉及跨时区场景时，必须始终以本地时间基准对齐两者，后续可考虑统一使用带时区标记的 ISO8601 或统一统一换算基准函数。
- **UI 状态一致性**：本次 UserToken 状态评级（正常/预警/危险/过期）逻辑纯粹、职责单一，建议后续将 `getTokenStatus` 下沉至公共 domain/model 目录，便于与后端预警通知联动。
